# docsite

A searchable HTML docs/examples site for this provider, generated by a single
Python **standard-library-only** script — no pip install, no virtualenv, no
build step required to view it.

## View it

Clone this repo, then open the file directly in a browser — no server needed:

```console
open docsite/output/index.html            # macOS
xdg-open docsite/output/index.html        # Linux
```

Or just double-click `docsite/output/index.html` in a file browser.

> GitHub does not render `.html` files inline when browsing github.com (it
> shows the source instead) — this only renders when opened locally like
> above, or if it's ever served (GitHub Pages, or any static host).

## Regenerate after changing examples/ or docs/

The `docsite/output/` directory is **committed** (there's no server to build
it on the fly), so re-run the generator and commit the diff whenever
`examples/` or `docs/resources` / `docs/data-sources` changes:

```console
python3 docsite/generate_site.py
```

It rebuilds `docsite/output/` from scratch every time, so it can never drift
from what's actually in the repo.

## Design

- `docsite/generate_site.py` — the generator (stdlib only: `pathlib`, `re`,
  `html`, `json`, `shutil`). Edit this to change page structure/content.
- `docsite/assets/style.css` — the site's visual design. Edit this directly
  to restyle; it's copied into `docsite/output/assets/` on every generate.
- `docsite/assets/search.js` — the client-side search box. Filters an
  embedded `search-index.js` (also generated) by title/section/snippet —
  works with no server since it's a plain `<script>` tag, not a fetch call.
- `docsite/output/` — generated, committed output. Don't hand-edit files in
  here; edit the generator or the assets instead and re-run it.

## If GitHub Pages ever gets unblocked

Nothing here needs to change — `docsite/output/` is a plain static site.
Point Pages at that folder (or copy it to a `gh-pages` branch) and it works
as-is.
