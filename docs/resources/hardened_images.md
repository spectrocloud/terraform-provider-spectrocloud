# spectrocloud_hardened_images (Resource)

  Resource for managing hardened image adoption across a tenant in Spectro Cloud. Palette propagates the Spectro Cloud registry image pull secret to every managed workload cluster so that clusters can pull hardened images. Use this resource to opt individual clusters out of that propagation and to observe the rollout status across the tenant.

Starting with Palette 4.9.b, Spectro Cloud ships hardened, minimal, continuously patched container images for system components, binaries, and packs. Pulling those images requires the Spectro Cloud registry image pull secret, which Palette distributes from the management appliance to every managed workload cluster in the tenant. See the [hardened images announcement](https://www.spectrocloud.com/blog/hardened-images-are-coming-to-palette-whats-changing-why-and-what-to-do) for background on the rollout.

Hardened image adoption is a tenant-level singleton, so declare at most one `spectrocloud_hardened_images` resource per tenant. Every cluster in the tenant is enrolled by default; list a cluster in `excluded_cluster_uids` to hold it back, and remove it from that list to enroll it again.

~> This resource is authoritative over the whole tenant. A cluster that someone opts out through the Palette console is picked up on the next refresh, and the following plan proposes re-enrolling it because it is absent from `excluded_cluster_uids`. Keep the full exclusion list in the configuration.

~> Palette has no operation that removes hardened image propagation, so destroying this resource only drops it from Terraform state. Clusters that were opted out stay opted out. To re-enroll a cluster, remove it from `excluded_cluster_uids` and apply before destroying the resource.

## Example Usage

An example of holding two clusters back from the hardened image rollout while every other cluster in the tenant is enrolled.

```hcl
resource "spectrocloud_hardened_images" "hardened_images" {
  excluded_cluster_uids = [
    "6512f1a3b0e4d8c7a9f21b40",
    "6512f1a3b0e4d8c7a9f21b57",
  ]
}

# Surface the clusters Palette could not deliver the image pull secret to
output "failed_hardened_image_clusters" {
  value = [
    for cluster in spectrocloud_hardened_images.hardened_images.clusters :
    cluster.name if cluster.state == "Failed"
  ]
}
```

## Import

In Terraform v1.5.0 and later, use an [`import` block](https://developer.hashicorp.com/terraform/language/import)
to import the resource spectrocloud_hardened_images by using the tenant `id`. For example:

```terraform
import {
  to = spectrocloud_hardened_images.hardened_images
  id = "tenant_uid"
}
```

Using `terraform import`, import the hardened image configuration using the `tenant_uid` or the organization name. For example:

```console
terraform import spectrocloud_hardened_images.example <tenant_uid>
terraform import spectrocloud_hardened_images.example <organization_name>
```

## Schema

### Optional

- `excluded_cluster_uids` (Set of String) Unique identifiers of the clusters that must not receive the hardened image pull secret. Palette keeps every other cluster in the tenant enrolled. Dropping an identifier from this set re-enrolls that cluster on the next apply.
- `timeouts` (Block, Optional) (see [below for nested schema](#nestedblock--timeouts))

### Read-Only

- `clusters` (List of Object) One entry per cluster in the tenant, reporting how far the hardened image pull secret rollout has progressed on that cluster. Clusters that are currently opted out are listed too. (see [below for nested schema](#nestedatt--clusters))
- `failed_clusters_count` (Number) Number of enrolled clusters that Palette could not deliver the image pull secret to. Inspect the `clusters` attribute for the per-cluster failure reason.
- `id` (String) The ID of this resource.
- `state` (String) Aggregated rollout progress for the tenant. Palette reports `Completed` once every enrolled cluster holds the secret, `InProgress` while the rollout is running, and `Failed` when at least one cluster could not be updated.
